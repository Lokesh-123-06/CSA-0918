# Assignment 4 – CO4 Report

## Task 1 – GUI design review (6)
Defects: UI, validation, payment and persistence are coupled; String action command is compared with == rather than equals; empty/nonnumeric/negative amounts are not checked; JDBC runs on the Event Dispatch Thread (EDT) and sleep freezes repaint/input; SQL concatenation permits injection; receipt action is not implemented; connection/statement are not closed; checked exceptions are not handled; no user-visible success/failure feedback; window close lifecycle is missing. Redesign: JFrame collects input; FeeService validates and delegates payment; DAO owns PreparedStatement/connection lifecycle; SwingWorker performs blocking I/O; completion callback updates UI on EDT. Separate button actions improve clarity. If k buttons share one action-command chain, dispatch may do up to O(k) comparisons; dedicated listeners use direct dispatch but create O(k) listener references.

## Task 2 – outpatient appointment desk (8)
Event map: department JComboBox → ItemEvent/ItemListener → refresh doctors; doctor/time JComboBoxes → Action/Item event → validate selection; Book JButton → ActionEvent/ActionListener → service booking; window close → WindowEvent/WindowAdapter → confirm if booking active. Component tree: JFrame(BorderLayout) contains patient form JPanel(GridLayout), department/doctor/time controls, Book button, status JLabel. Pseudocode: on department change, look up doctors from Map<Department,List<Doctor>>, replace doctor model and clear selection. On book, validate patient ID, doctor, slot; disable button, submit service call, show confirmation/error and re-enable. WindowClosing asks confirmation if operation is in progress. Applet init/start/paint/stop/destroy are lifecycle callbacks, unlike a desktop window's constructor/visibility/events/dispose. Preloading doctors costs O(d+m) memory and O(1) average lookup; fetching per change costs network/database latency each time.

## Task 3 – Library layout (9)
Use JFrame BorderLayout; title NORTH, search row NORTH within a header panel, results JScrollPane CENTER, navigation FlowLayout SOUTH, status SOUTH or within footer. Nested panels preserve fixed-height controls while CENTER expands. GridLayout forces equal cells and is not suitable for the whole screen; CardLayout suits alternate views; absolute positioning breaks resizing. GridBagLayout is flexible but more complex. Layout traversal is O(number of components); nested panels add O(c) container references. Validate at three sizes on local desktop and add screenshots.

## Task 4 – Drawing pad forensics (7)
The handler method is misspelled mouseclicked; Java requires mouseClicked, so it does not override the listener method. getGraphics draws transient pixels that disappear on repaint. Store Point objects, update label, call repaint, and draw all points in paint(). @Override makes the typo a compile-time error. Repainting n stored points is O(n); a BufferedImage uses O(width×height) pixel memory and can be copied per repaint in O(image pixels), with incremental drawing on each click.

## Task 5 – Currency converter event styles (7)
Implement frame listener, named inner class, anonymous listener and lambda. All use the same conversion service and WindowAdapter. Add Enter action to the text field and use JOptionPane for result. Frame listener is simple for tiny windows but couples concerns; named inner class is reusable and testable; anonymous class is local but verbose; lambda is concise for functional interfaces. A shared Action/method reference can serve button, menu and shortcut with one behaviour object.

## Task 6 – Event registration app (13)
Layering: RegistrationFrame (JFrame/JTable/JMenuBar) → RegistrationService (validation and duplicate policy) → RegistrationDao (JDBC PreparedStatement). Unique database constraint on (student_id,event_id) is the final duplicate guard. SwingWorker executes DB access off EDT; done() updates model and dialogs on EDT. Register pseudocode: validate fields; disable submit; execute service in SwingWorker; on success refresh page and show confirmation; on duplicate show clear message; re-enable. Filter uses allow-listed event ID and parameterised LIMIT/OFFSET. For 100,000 rows, loading all rows consumes O(n) UI objects and blocks/overloads memory; pagination loads O(pageSize) rows per page and keeps the UI responsive. SQL uses ORDER BY with LIMIT/OFFSET; keyset pagination is preferable for deep pages.
